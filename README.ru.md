# FermentPressureTool

Устройство для мониторинга и управления процессом ферментации с измерением давления и температуры в режиме реального времени.

## 📋 Описание проекта

**FermentPressureTool** — это IoT-устройство на базе ESP32, разработанное для точного контроля условий ферментации. Устройство позволяет отслеживать давление и температуру в емкости для ферментации, передавать данные в облачные сервисы и управлять клапаном сброса давления.

### Основные возможности:

- 📊 **Мониторинг давления** — чтение аналогового датчика давления через АЦП
- 🌡️ **Измерение температуры** — поддержка датчика DS18B20 через OneWire
- 📡 **Облачная интеграция** — отправка данных в:
  - **Brewfather** (платформа для пивоваров)
   - **ThingSpeak** (IoT платформа)
  - **Пользовательский HTTP API** (гибкая интеграция)
- 🖥️ **Веб-интерфейс** — управление и мониторинг через браузер
- 🔧 **Конфигурационный портал** — WiFi конфигурация без перепрошивки
- 📱 **OLED дисплей** — попеременное отображение давления и температуры (SSD1306, 128x64)
- 🤖 **Многопоточность** — параллельное выполнение сенсорных и сетевых операций
- 💾 **Сохранение настроек** — Preferences/NVS для хранения конфигурации

## 🛠️ Аппаратное обеспечение

### Основной микроконтроллер
- **ESP32-DevKit** — WiFi-enabled, двухъядерный микроконтроллер

### Датчики и модули
- **Датчик давления** — аналоговый, подключен к `GPIO34` (ADC1_CH6)
- **Внешний АЦП (опционально)** — ADS1115 на общей I2C-шине с OLED (адрес `0x48`, вход давления `A0`)
- **Датчик температуры** — DS18B20 (OneWire)
   - DATA: `GPIO4`
   - Между DATA и VCC нужен подтягивающий резистор 4.7 кОм
- **OLED дисплей** — SSD1306 128x64 (I2C, адрес 0x3C)
- **Соленоидный клапан** — управление через `GPIO27`

### Подключение
- Последовательное соединение (UART) для отладки на скорости 115200 бод
- CH340 USB-UART конвертер для программирования

### Кнопки ферминатора через PC817

Для текущей прошивки **ESP32-S3-mini** выделены четыре ранее не использовавшихся GPIO:

| Канал | GPIO ESP32-S3 | Штатная кнопка |
|-------|--------------|---------------|
| 1 | 10 | Температура + |
| 2 | 11 | Температура − |
| 3 | 12 | Start/Stop |
| 4 | 13 | Fan Speed |

Актуальные остальные подключения S3: давление GPIO1, DS18B20 GPIO2, локальная I2C-шина
SDA GPIO5 / SCL GPIO4, клапан GPIO6, пассивный захват OLED SDA GPIO9 / SCL GPIO8.
Приведённые выше GPIO34/GPIO27 относятся к старой версии ESP32, не к текущей сборке.

Включите **Main Settings → Ferminator Control**. Под зеркалом OLED появятся кнопки,
расположенные как на пульте: «+» / «−» слева, Start/Stop / Fan Speed справа.
Каждый клик формирует один импульс HIGH длительностью **200 мс**, затем выход возвращается
в LOW. Минимальный интервал между импульсами — 200 мс. Удержания, автоповтора, установки
абсолютной температуры или скорости нет: всё обрабатывает штатный контроллер ферминатора.
Результат проверяется по его экрану; успешный HTTP-ответ подтверждает только отправку импульса.
При ошибке связи команда не повторяется автоматически, поскольку Start/Stop может уже сработать.

**Согласование входов:** у модуля Hailege PC817 по ссылке B0CJY4G9LS заявлен диапазон
**3,6–30 В**. GPIO ESP32 выдают 3,3 В; напрямую подключать такой вход без подтверждения
его характеристик нельзя. Используйте по одному NPN-транзистору на канал:
вход «+» PC817 к +5 В, вход «−» к коллектору, эмиттер к GND ESP32/источника 5 В,
GPIO через базовый резистор (например, 2,2 кОм) к базе. Между базой и эмиттером
установите 10 кОм, чтобы исключить включение при сбросе/плавающем GPIO.
Номиналы и допустимый ток проверьте по схеме именно вашей платы; резисторы входных LED
обычно уже установлены на модуле. Не подавайте 5 В на GPIO ESP32.

**Выходы:** изолированный транзистор каждого PC817 подключается параллельно контактам
соответствующей штатной кнопки, коллектором к более положительному контакту, эмиттером
к более отрицательному. Перед подключением измерьте полярность и проверьте схему пульта:
PC817 не является универсальным двунаправленным «сухим контактом» для любой матрицы.
Проверьте перемычки и выходные подтяжки модуля: они не должны подавать внешнее питание
в цепь кнопок. Без схемы модуля нельзя считать маркировку OUT/GND эквивалентной свободным
выводам коллектора/эмиттера. Землю выходов не соединяйте с ESP32 только ради кнопок;
другие соединения, например захват OLED, могут уже объединять земли.

API: `POST /ferminator/button`, тип `application/x-www-form-urlencoded`,
тело `button=temp_up`, `button=temp_down`, `button=start_stop` или `button=fan_speed`.
Ответы: 200 — импульс завершён; 400 — неизвестная кнопка; 403 — функция отключена;
429 — слишком частая команда; 503 — контроллер/настройки недоступны.
GPIO переводятся в LOW в начале загрузки даже при отключённой функции.
Используйте только доверенную локальную сеть: отдельной авторизации, как и у существующего
API управления клапаном, здесь нет.

### Выбор АЦП давления

В веб-настройках можно выбрать встроенный АЦП ESP32 или внешний ADS1115.
В режиме ESP32 сохраняется существующий делитель напряжения на `GPIO34`. В режиме ADS1115
датчик давления подключается напрямую к `A0`, делитель не используется, так как вход рассчитан
на сигнал датчика 0.5-4.5 В. Подключите `VDD`, `GND`, `SDA` и `SCL` к плате, а `ADDR` соедините
с `GND`, чтобы получить адрес `0x48`. ADS1115 и ESP32 должны иметь общий GND. Не превышайте
напряжение питания ADS1115 и допустимые абсолютные пределы его входа.

### Диапазон датчика давления

На вкладке основных настроек в разделе **Sensor & Calibration** укажите в поле
**Sensor Max Pressure (PSI)** верхний предел давления, указанный на датчике (например,
`100` для датчика 0–100 PSI). Значение по умолчанию — `100` PSI, в том числе после
обновления существующих устройств. Допускается положительное конечное число; настройка
сохраняется в NVS и применяется без перезагрузки для обоих АЦП. Единица этой настройки
всегда PSI, независимо от единицы отображения. Диапазон сигнала 0.5–4.5 В и калибровка
смещения напряжения не меняются. Порог срабатывания клапана настраивается отдельно.
API возвращает `sensorMaxPsi` в `GET /api` и принимает его через `POST /api`.

### Рекомендуемые настройки для внешнего АЦП

При использовании внешнего ADS1115 рекомендуются следующие настройки для стабильного и
отзывчивого измерения давления:

- Median Sample Count (нечетное, 3-31): `5`
- Median Sample Delay (ms): `10`
- Update Interval (ms): `50`

Эти значения помогают подавить шум датчика и при этом сохранить достаточную скорость обновления
для мониторинга ферментации и управления давлением.

При использовании внешнего ADS1115 адаптивный фильтр можно отключить, если сам АЦП уже дает
стабильный сигнал и дополнительное сглаживание не требуется.

## 🔌 Компоненты ПО

### CloudManager
Управляет отправкой данных на облачные платформы. Поддерживает несколько одновременных провайдеров.

### ConfigPortal
WiFi конфигурационный портал для первоначальной настройки и переконфигурации сетевых параметров без необходимости перепрошивки.

### SensorManager
- Инициализация АЦП и калибровка из eFuse
- Фильтрованное чтение давления (среднее по N сэмплам)
- Чтение температуры с датчика DS18B20 через OneWire

### DisplayManager
Управление OLED дисплеем SSD1306 для попеременного отображения давления и температуры. Интервал переключения настраивается в веб-интерфейсе.

### WebServer
REST API для:
- Получения текущих данных датчиков
- Управления клапаном
- Изменения параметров системы
- Отправки данных в облако

### SolenoidController
Управление соленоидным клапаном для сброса давления.

```
adafruit/Adafruit SSD1306 @ ^2.5.9
adafruit/Adafruit GFX Library @ ^1.11.9

paulstoffregen/OneWire @ ^2.3.8
milesburton/DallasTemperature @ ^4.0.4
```

### Сборка и загрузка

1. **Откройте проект в VS Code**
   ```bash
   code d:\Projects\FermentPressureTool
   ```

2. **Подключите ESP32 через USB**

3. **Выберите окружение в PlatformIO**
   - Выберите `esp32s` из доступных окружений

4. **Соберите проект**
   ```bash
   pio run -e esp32s
   ```

5. **Загрузите прошивку**
   ```bash
   pio run -e esp32s --target upload
   ```

6. **Откройте монитор последовательного порта**
   ```bash
   pio device monitor -e esp32s
   ```

### Зеркало OLED ферминатора
- В **Main Settings** настройка **Ferminator Control** («Управление ферминатором») по умолчанию выключена, в том числе после обновления без ранее сохранённого значения. Включайте её только на контроллере, подключённом к ферминатору; значение хранится отдельно в NVS каждого устройства.
- В выключенном состоянии блок OLED ферминатора не формируется в странице, задача/прерывание захвата и прослушивание GPIO8/9 не запускаются, `/oled` возвращает HTTP 403, а поля состояния и статистики OLED ферминатора отсутствуют в `/api`. Контроль давления/клапана, локальный OLED, опциональный датчик температуры и облачные интеграции продолжают работать.
- Изменение настройки сохраняется и автоматически перезагружает устройство; портал ожидает восстановления связи и обновляет страницу. Сохранение того же значения не вызывает перезагрузку. Настройка включает уже реализованное зеркало OLED, но не пока ещё не реализованные кнопки через оптопары.
- `GPIO8` подключается к SCL, `GPIO9` — к SDA шины ферминатора.
- Эти линии только прослушиваются: прошивка не запускает на них I2C-мастер и не отправляет ACK или данные.
- Подключение выполняется параллельно шине OLED; нужен общий GND. Входы ESP32 рассчитаны на 3,3 В — не подключайте напрямую шину с подтяжками к 5 В.
- Поддерживается SH1106 128x64 (адрес `0x3C` или `0x3D`). Учитывается внутренняя RAM шириной 132 столбца и смещение видимых 128 столбцов на 2. После захвата всей видимой области экран появляется в веб-портале.
- Ориентация учитывает монтаж модуля для A1/C8. Параметры кадра передаются вместе с пикселями в заголовках `X-OLED-*`, а не берутся из отдельного запроса состояния.
- `/oled` по-прежнему возвращает 1024 байта RAM постранично. Заголовки: `X-OLED-Sequence`, `X-OLED-Start-Line`, `X-OLED-Display-Offset` и `X-OLED-Flags` (биты 0–4: экран включён, все точки включены, инверсия, переназначение сегментов, обратное сканирование COM).
- Параметры команд могут передаваться отдельными I2C-транзакциями. Ошибка захвата сбрасывает только собираемое обновление: последний принятый кадр остаётся доступным со своими временем и номером.
- Захват использует выделенное GPIO-прерывание уровня 3 в IRAM на ядре setup (ядро 1), отдельно от Wi-Fi/облаков, вместо обработчиков Arduino. Опрос ADC/OneWire выполняется на ядре 0, чтобы не блокировать прерывания захвата. Захват занимает источник GPIO-прерываний; совместное использование с `attachInterrupt`/GPIO ISR service потребует переработки.
- Прерывание START запускает прямое чтение GPIO до STOP, с ограничением 20 мс на транзакцию. Это исключает задержку вызова обработчика на каждом фронте, но может задерживать другую работу ядра 1 до 20 мс. Целевой режим стенда — 100 кГц и порции данных до 128 байт; более длинные передачи/растяжение тактов могут превысить тайм-аут.
- Незавершённые байты, тайм-ауты захвата, некорректные передачи и переполнения сбрасывают покрытие кадра. `oledCaptureErrors` в `/api`, статус веб-зеркала и Serial показывают потерю синхронизации отдельно от переполнений. Не все искажения байтов обнаружимы: у I2C нет контрольной суммы данных.
- Публикация требует одного полного последовательного обновления видимой RAM: от страницы 0/столбца 2 до страницы 7/столбца 129, затем паузы не менее 3 мс. Пропуск, повтор адреса или начало нового обновления отбрасывают собираемый кадр, а не объединяют покрытие разных обновлений. Это намеренно рассчитано на полнокадровые драйверы вроде стенда; только частичные обновления или другой порядок страниц не публикуют новые кадры.
- `/api` содержит `oledDroppedFrames` и `oledRecovering`. При повторном захвате веб явно удерживает последний целый кадр, не скрывая ошибки захвата. После выбора страницы для приёма данных требуются обе части адреса столбца.
- `oledFrameTiming` считает успешные публикации полных кадров независимо от запросов браузера: число кадров/интервалов, длительность наблюдения, текущее ожидание, последний/минимальный/средний/максимальный завершённый интервал (миллисекунды) и шесть непересекающихся диапазонов (`<=1500`, `1501-3000`, `3001-5000`, `5001-10000`, `10001-30000`, `>30000` мс). До двух успешных кадров интервальные показатели равны `null`. Текущее незавершённое ожидание ещё не входит в статистику завершённых интервалов.
- `OledMirrorConfig::SHOW_DEBUG_INFO` в `src/config.h` управляет подробной отладочной информацией OLED в портале (по умолчанию `false`). Для отображения интервалов кадров, счётчиков захвата, покрытия байтов и возраста кадра установите `true`, пересоберите и загрузите прошивку. Основной статус и ошибки чтения кадров видны в обоих режимах; флаг не меняет логирование в Serial.
- Статистика накапливается в RAM до перезагрузки и не сбрасывается при обновлении или закрытии браузера, даже когда отладочное отображение выключено. Она остаётся доступна через `/api`, а при включённом отладочном отображении видна под статусом OLED. Записи во flash и логирование каждого кадра в Serial не нужны. Для получасового прогона оставьте приёмник включённым, затем прочитайте `/api` без перезагрузки устройства.
- При подключении после инициализации OLED (или потере синхронизации) настройки дисплея неизвестны. Веб явно обозначает предпросмотр RAM и использует порядок RAM для неизвестных настроек, а не считает экран выключенным. Для захвата реальной конфигурации перезапустите источник, оставив приёмник включённым.
- `X-OLED-Known-State` / `oledKnownState` — битовая маска: биты 0–6 означают захваченные настройки включения, сегментов, сканирования COM, начальной строки, смещения, инверсии и включения всех точек. Значение 127 означает, что захвачены все настройки.
- Тесты веб-зеркала: `node --test test\oled_mirror.test.cjs`. Точность GPIO-захвата необходимо дополнительно проверять на реальной шине I2C.
- Проверки порядка кадров на этапе компиляции C++: `xtensa-esp32s3-elf-g++ -std=c++11 -fconstexpr-depth=2048 -Wall -Wextra -Werror -Isrc -fsyntax-only test\oled_frame_coverage.cpp` (используйте компилятор из PlatformIO toolchain).

### Облачные интеграции
Настройте ключи API и параметры в конфигурационном портале или через веб-интерфейс:
- **Brewfather API Key**
- **ThingSpeak Channel ID и API Key**
- **Custom HTTP URL endpoint**

### OLED и датчики
- Давление и температура на OLED отображаются попеременно.
- Интервал переключения настраивается в веб-интерфейсе, по умолчанию 3 секунды.
- Если датчик температуры отключен, отображается только давление.
- Если датчик давления не подключен, на экране показывается `Disconnected`, а данные в облака не отправляются.
- OLED ферминатора пассивно копируется в веб-портал через `GPIO8`/`GPIO9`.

## 🌐 Облачная интеграция

### Brewfather
Интеграция с популярной платформой для пивоваров. Отправляет данные о давлении и температуре. Поле температуры можно выбрать: ферментер (`temp`), внешняя температура (`ext_temp`) или холодильник (`aux_temp`).

### ThingSpeak
IoT платформа для хранения и визуализации данных. Поддерживает историю измерений и графики.

### Пользовательский HTTP API
Гибкая интеграция с любым HTTP API для отправки данных в пользовательский бэкенд.

## 📊 REST API

### Получить данные датчиков
```
GET /api
```

Ответ:
```json
{
  "pressure": 1.5,
  "temperature": 22.5,
   "voltage": 2.3,
   "pressureConnected": true,
   "tempConnected": true
}
```

### Получить кадр OLED ферминатора
```
GET /oled
```
Возвращает видимую область SH1106 размером 1024 байта (`application/octet-stream`); четыре невидимых столбца RAM в ответ не включаются.
Статус захвата и номер версии кадра доступны в ответе `GET /api`.

### Управление клапаном
```
POST /api
Body: cmd=manual_on
```

### Отправить данные в облако
Облачная отправка выполняется автоматически в рабочем цикле прошивки и пропускается, если датчик давления отключен.

## 🔄 Архитектура многопоточности

Система использует задачи на двух ядрах ESP32:
- **Core 1**: Прерывание пассивного захвата OLED
- **Core 0**: Сенсорные операции (чтение датчиков, управление клапаном)
- **Core 0**: Сетевые операции (WiFi, облачные запросы, веб-сервер) и декодирование захваченной шины OLED

Синхронизация через структуру `RuntimeState` с использованием семафоров.
